# CareSignal-Waist — เซ็นเซอร์คาดเอว (Arduino Nano 33 BLE Sense Rev2)

อุปกรณ์วิจัย/ตรวจสอบความแม่นสำหรับ CareSignal V3: รัดที่เอวผู้สูงอายุขณะทำ
ลุกนั่ง 5 ครั้ง · ลุกเดิน 3 เมตร · ท่าทรงตัว แล้วส่งค่าที่ห้องตรวจการเคลื่อนไหววัดกัน
(instrumented 5×STS · instrumented TUG · การแกว่งขณะยืน) ไปยังแอปทางบลูทูธ

**บทบาท:** เครื่องมือของทีมสำหรับนำร่องและพิสูจน์ความแม่นของกล้อง ไม่ใช่อุปกรณ์ที่แจกให้
ผู้เอาประกันใส่ประจำ — โมเดลธุรกิจยังคง "ใช้มือถือที่มีอยู่แล้ว" · การวัดด้วยกล้องและการกดจับเวลา
ยังอยู่ครบ (iPhone ต้องใช้สองวิธีนั้น เพราะ Safari ไม่รองรับ Web Bluetooth)

## รุ่น 1.1 — การทดสอบมาตรฐาน 5 ท่า

| ท่า | มาตรฐานอ้างอิง | ค่าที่ได้ | เกณฑ์ที่แสดง |
|---|---|---|---|
| 1 ลุกนั่ง 5 ครั้ง (5×STS) | instrumented 5×STS (Van Lummel 2013) | เวลารวม · เวลาแต่ละครั้ง · ช่วงลุก · ความเร็วก้มลำตัว · ดัชนีกำลัง · CV | ค่าตัดตามอายุ 10.0/11.5/12.1 วิ |
| 2 ลุกเดิน 3 เมตร (TUG) | CDC STEADI · iTUG (Salarian 2010) | ลุก · เดินไป · หมุน (องศา เวลา) · เดินกลับ · หมุนก่อนนั่ง · นั่ง · ก้าว · จังหวะ | ≥ 12 วิ = เสี่ยง |
| 3 ทรงตัว 4 ท่า | CDC 4-Stage Balance · ISway (Mancini 2012) | เวลา · RMS · แกนหลัก/รอง · พื้นที่ 95% · jerk · ความถี่ · ธงขยับตัว | ต่อเท้าไม่ครบ 10 วิ = เสี่ยง |
| 4 ลุกยืน 30 วินาที | CDC STEADI 30-Second Chair Stand | จำนวนครั้ง (นับครั้งที่ลุกเกินครึ่งทางตอนครบเวลาตามกติกา CDC) | ตารางค่าต่ำกว่าเฉลี่ยตามอายุ/เพศของ CDC |
| 5 เดิน 4 เมตร | World Guidelines for Falls Prevention 2022 | เวลา · ความเร็ว · จังหวะก้าว · CV ของก้าว | < 0.8 ม./วิ = เดินช้า |

**สิ่งที่เพิ่มในรุ่น 1.1**
- **ชดเชยค่าคลาดไจโร (gyro bias)** จากช่วงนิ่ง 1 วินาทีก่อนทุกท่า — BMI270 ที่ยังไม่ปรับเทียบคลาดได้ 1–2 องศา/วิ ซึ่งทำให้มุมหมุนตัวเพี้ยน ตอนนี้ผลบอกขนาดค่าคลาดไว้ตรวจคุณภาพด้วย
- **ตรวจเครื่องก่อนใช้ (self-test)** — วางบอร์ดนิ่ง 2 วินาที ตรวจ 4 ข้อ: อัตราสุ่ม 90–110 Hz · แรงโน้มถ่วง 1 ± 0.05 g · ค่าคลาดไจโร ≤ 3 องศา/วิ · สัญญาณรบกวนไจโร ≤ 0.5 องศา/วิ ควรทำทุกเช้าก่อนเก็บข้อมูลและบันทึกผลไว้
- **ใช้ผ่านสาย USB ได้โดยไม่มีโทรศัพท์** — Serial Monitor 115200 พิมพ์ `1`–`5` เลือกท่า `g` เริ่ม `x` หยุด `p` ตรวจเครื่อง `r` ข้อมูลดิบ CSV 100 Hz · ผลออกเป็นบรรทัด `RESULT,…`
- **หน้าห้องทดสอบ `sensor-lab.html`** (โหมดวิจัย) — ทำครบ 5 ท่า กรอกเวลาที่เจ้าหน้าที่จับได้เป็นค่าอ้างอิงทุกครั้ง เห็นความต่างทันที และส่งออก CSV สำหรับวิเคราะห์ Bland–Altman
- แพ็กเก็ตผลรุ่น 2 (84 ไบต์เท่าเดิม) · แอปอ่านได้ทั้งรุ่น 1 และ 2

**ทดสอบ:** `node test/test_imu.mjs` — 69 ข้อ ด้วยสัญญาณจำลองที่รู้คำตอบ (นับลุกยืน 30 วิ ตรงกติกาครึ่งทาง · ความเร็วเดินคลาดไม่เกิน 12% ที่ 0.6/1.0/1.3 ม./วิ · ประมาณค่าคลาดไจโรคลาดไม่เกิน 0.2 องศา/วิ · ค่าคงที่ C กับ JS ตรงกันทุกตัว)

> ⚠️ **ยังไม่เคยคอมไพล์และยังไม่เคยลองกับบอร์ดจริง** — ผลการทดสอบข้างบนเป็นของแกนคำนวณฝั่ง JS ซึ่งเป็นฝาแฝดของ C
> ก่อนใช้กับผู้สูงอายุ: คอมไพล์ → อัปโหลด → ตรวจเครื่อง → ลองทั้ง 5 ท่ากับทีมเองเทียบกับนาฬิกาจับเวลา

## ไฟล์

| ไฟล์ | คืออะไร |
|---|---|
| `CareSignal-Waist.ino` | สเก็ตช์ Arduino: อ่าน BMI270 100 Hz · BLE service · คำสั่งผ่าน USB · ตรวจเครื่อง · ไฟสถานะ |
| `cs_imu_core.h` | แกนคำนวณ (C ล้วน) — **ฝาแฝดของ `cs-imu.js` ในแอป** ค่าคงที่ต้องตรงกัน (`node test/test_imu.mjs` ตรวจให้) |

## ของที่ต้องมี

- Arduino Nano 33 BLE Sense **Rev2** (BMI270 + BMM150) — รุ่นแรก (LSM9DS1) ใช้ไลบรารีคนละตัว
- สายไมโคร-USB · **พาวเวอร์แบงก์ขนาดเล็ก** (2,000 mAh พอทั้งวัน) — ไม่ต้องบัดกรีแบตเตอรี่/วงจรชาร์จ
- กล่องพลาสติกเล็ก + คลิปหนีบเข็มขัด หรือกระเป๋าคาดเอว
- มือถือ Android ที่มี Chrome (Web Bluetooth) · หรือคอมพิวเตอร์ที่มี Chrome

## ติดตั้งโปรแกรมลงบอร์ด

1. Arduino IDE 2.x → Boards Manager → ติดตั้ง **Arduino Mbed OS Nano Boards**
2. Library Manager → ติดตั้ง **ArduinoBLE** และ **Arduino_BMI270_BMM150**
3. เปิด `CareSignal-Waist.ino` → เลือกบอร์ด *Arduino Nano 33 BLE* → พอร์ต → Upload
4. ไฟน้ำเงินกะพริบ = พร้อมเชื่อมต่อ (ชื่ออุปกรณ์ `CareSignal-Waist`)

## วิธีติดที่เอว

- ติดที่ **เอวด้านหลัง ระดับเข็มขัด (ใกล้ L3–L5)** ให้แน่น ไม่แกว่ง — ตำแหน่งมาตรฐานของงานวิจัย
- ทิศของบอร์ดไม่สำคัญ (โปรแกรมหาแนวตั้งจากแรงโน้มถ่วงเอง) แต่ต้องไม่ขยับระหว่างการวัด
- ก่อนเริ่มทุกท่า อุปกรณ์ขอให้ **นิ่ง 1 วินาที** เพื่อตั้งศูนย์ ถ้ายังขยับจะขอใหม่

## โปรโตคอล BLE (สรุป)

UUID ฐาน `c5a1xxxx-3b1e-4c1a-9b6c-0000ca7e5161`

| xxxx | ชื่อ | ทิศ | เนื้อหา |
|---|---|---|---|
| 0001 | CTRL | เขียน 4 ไบต์ | `[cmd, arg1, arg2, 0]` — 1 ARM(kind, stage) · 2 GO · 3 STOP · 4 STREAM(on) · 5 RESET |
| 0002 | STATE | notify 16 ไบต์ / 100 ms | kind · phase · count · elapsed · tilt · omega_h · yaw · event · flags |
| 0003 | RESULT | read/notify 84 ไบต์ | โครงใน `cs_imu_core.h` — แอปอ่านค่าเต็มด้วย `readValue()` |
| 0004 | RAW | notify 14 ไบต์ / 50 Hz | t · ax ay az (mg) · gx gy gz (0.1 องศา/วิ) |
| 0005 | INFO | read | สตริงรุ่นเฟิร์มแวร์ |

## สิ่งที่ตั้งใจไม่ทำ

- **ไม่ใช้ไมโครโฟน** บนบอร์ด (ระบบ CareSignal ไม่มีเสียงสั่งการ) — เทสต์ในแอปตรวจว่าโค้ดไม่แตะ PDM
- ไม่เก็บข้อมูลในบอร์ด ไม่มีชื่อ/รหัสผู้ใช้ในบอร์ด — บอร์ดรู้แค่ "ท่าที่กำลังวัด"
- ไม่อ้างว่า "ตรวจจับการล้ม" เป็นคุณสมบัติ — ธงแรงกระแทกมีไว้ให้ผู้ดูแลตรวจสอบระหว่างทดสอบเท่านั้น

## ข้อจำกัดที่ต้องบอกกรรมการ/แพทย์ตรงไปตรงมา

- iPhone ยังเชื่อมต่อผ่านเว็บไม่ได้ (ต้องใช้ Android Chrome หรือคอมพิวเตอร์)
- ความเร็วเดินเป็นค่าประมาณจากระยะ 3 ม. ในท่า TUG ไม่ใช่ทดสอบเดิน 4 ม. มาตรฐาน
- ค่าจากเซ็นเซอร์ตัวเดียวที่บ้าน ยังไม่ผ่านการเทียบกับห้องตรวจการเคลื่อนไหวในกลุ่มผู้สูงอายุไทย —
  นี่คือสิ่งที่การนำร่องจะพิสูจน์ ใช้เทียบแนวโน้มของคนเดียวกันได้ทันที
- อุปกรณ์วิทยุที่จะจำหน่ายจริงต้องผ่าน กสทช. — ชุดนี้เป็นเครื่องมือวิจัยของทีม
