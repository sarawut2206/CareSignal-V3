## ทำไมต้องมี V3

ภารกิจ Idea Validation (15–16 ก.ย. 2569) สัมภาษณ์ผู้สูงอายุ 3 คน (อายุ 60, 65, 68) และลูกหลานผู้ดูแล 2 คน:

- 5/5 มีผู้สูงอายุหกล้มในปีที่ผ่านมา · 5/5 อยากประเมินได้ที่บ้าน
- 3/3 ผู้สูงอายุติดตั้งแอปหรือตั้งกล้องเองไม่ได้ ("กดไม่เป็น" · "ตั้งกล้องไม่เป็น")
- 3/3 ผู้สูงอายุเลือก "ให้ลูกหลานรู้" เป็นฟีเจอร์อันดับ 1

จึงเปลี่ยนผู้ใช้จากผู้สูงอายุเป็นลูกหลาน และยกทางสำรอง "จับเวลาด้วยมือ" ของ V2 ขึ้นเป็นทางหลัก

## หลักการเดิมที่ยังอยู่

- ไม่วินิจฉัยโรค ไม่แทนการพบแพทย์ · ฉุกเฉินโทร 1669 ไม่มี "ทีมฉุกเฉิน" ของระบบ
- ข้อมูลบันทึกในเครื่องของลูกหลานก่อน (`localStorage`) แล้วส่งขึ้นระบบกลางเมื่อเชื่อมบัญชี

## ระบบกลางและการส่งต่อ (เหมือน V2)

V3 ใช้ Supabase โปรเจกต์เดียวกับ V2 (`cs-backend.js` ไฟล์เดียวกัน) ผ่านชั้นเชื่อม `cs-cloud.js`

- บัญชี 1 บัญชี = ผู้สูงอายุ 1 คน ลูกหลานเป็นผู้ดูแลบัญชี (เบอร์โทร + PIN 4 หลัก ตามระบบยืนยันตัวตนของ V2) · `profiles.carer_name/carer_phone` เก็บว่าใครวัดให้
- ผลวัด → `assessments` (`method='manual'`, `detail.measured_by='carer'`) → `risk_signals` → ทริกเกอร์ `open_case_on_signal` เปิดเคสในคอนโซลเจ้าหน้าที่ V2 → ระดับส้ม/แดงสร้าง `referrals`
- "บันทึกว่าล้ม" → `care_events(kind='fall')` → ทริกเกอร์ใหม่ `open_case_on_fall_event` (migration 23) เปิดหรือยกระดับเคสทันที
- ต้องรัน `supabase/23_v3_carer.sql` บนโปรเจกต์หนึ่งครั้ง (รันซ้ำได้) — ถ้ายังไม่รัน แอปยังส่งผลได้ แต่การล้มจะไม่เปิดเคสอัตโนมัติ
- ทุกสัญญาณเสี่ยงแสดงเหตุผลและที่มา ไม่ใช่ AI ทำนาย
- ค่าจับเวลาที่ผิดปกติ (เช่น 0 วินาที) จะถูกถามยืนยันก่อนบันทึก
